# 课程分类和资料管理依赖分析

> 任务书决策：① 取消后台独立「课程分类」管理入口（不删分类表/字段）；② 暂时隐藏后台「资料管理」入口（不删底层代码/表/R2 文件/下载接口）。本文档列出全部依赖点与安全方案。

---

## 一、课程分类依赖分析

### 1. 数据层依赖

| 依赖点 | 位置 | 说明 |
| --- | --- | --- |
| `contents.category_id` → `content_categories.id` | `db/schema.sql` L102 | 可空外键，课程的分类归属 |
| `resources.category_id` → `content_categories.id` | `db/schema.sql` L143 | 可空，资料的分类归属 |
| 分类表本身 | `content_categories` | `type` = course / resource / tool；`slug` UNIQUE；`sort_order` 排序 |
| 初始数据 | `schema.sql` L242-253 | 10 个 course 分类 + sop/prompt 2 个 resource 分类 |

### 2. 服务端依赖（`public/_worker.js`）

| 功能 | 位置 | 对分类的依赖 |
| --- | --- | --- |
| 会员课程数据加载 | `loadCourseData` L2362 | 读 `type='course'` 分类，按分类分组课程；会员首页（L2415）、课程列表（`renderCourseIndex` L2513）、更新页（`renderUpdates` L2901）都用 |
| 会员首页 SOP 区 | `renderMemberHome` L2419-2422 | 按分类 slug ∈ {sop, prompt} 过滤课程 |
| 会员资料库 / SOP 页 | `loadPublishedResources` L2386 | 按分类 slug 过滤资料（`/member/app/sop/` 传 ["sop","prompt"]） |
| 公开课程列表 | `handlePublicCourseList` L3252 | LEFT JOIN 取分类名展示 |
| 公开课程详情 | `handlePublicLibrary` L3125 | LEFT JOIN 取分类名展示（面包屑/标签） |
| 公开栏目页 | `handleNavSection` L3320 | LEFT JOIN 取分类名展示（过滤用的是 `nav_category` 字段，**不是分类表**） |
| 会员课程详情 | `renderCourseDetail` L2666 | LEFT JOIN 分类名；同分类 sibling 课程导航（L2686） |
| 后台课程列表 | `GET /api/admin/contents` L4764 | LEFT JOIN 分类名 + 分类 sort_order（固定分组显示） |
| 后台分类 CRUD | `/api/admin/categories` L4617-4742 | 列表/新建/编辑/删除（占用检查）/迁移删除 |
| 后台概览 | `GET /api/admin/overview` L4477 | 统计含分类数据 |
| 后台课程表单 | `adminContentBody` L1733 附近 | 分类下拉由 `admin.js` 从 `/api/admin/categories` 加载 |

### 3. 前端依赖（`public/assets/js/admin.js`）

- `initContent`（L975）：打开课程表单时请求 `/api/admin/categories` 填充分类下拉；课程列表固定按分类分组显示（二期第三轮已固化）。
- `initCategoriesPage`（L1250）+ `initCategoryManagement`（L1254）：独立分类页 `/admin/categories/` 的全部交互。

### 4. 结论：能否取消后台独立入口？

**可以安全取消「入口」，不能删数据和接口。** 依赖链：

- 课程的展示、分组、前台筛选 **只依赖分类表数据存在**，不依赖管理员能否编辑分类。
- 课程表单的分类下拉 **依赖 `GET /api/admin/categories` 接口**。
- 会员端 SOP 筛选 **依赖 sop/prompt 两个分类 slug 不被改名**。

**安全方案（第二阶段执行）：**

1. 仅移除后台导航中的「课程分类」菜单项（`adminShell` 导航数组 L1530-1540 删一行）+ 删除/保留 `/admin/categories/` 页面路由均可（建议保留路由但不出现在导航，作为隐藏入口应急）。
2. 保留：`content_categories` 表、`/api/admin/categories*` 全部接口、课程表单分类下拉、固定分组展示。
3. 注意事项：
   - 取消入口后分类将不可再编辑/新增/排序，现有 10 个课程分类固化。
   - sop/prompt 两个资源分类若改名会影响会员端 SOP 页筛选，隐藏入口后该风险自然消除。
   - 若未来彻底不要分类，需要额外迁移课程表单（去下拉）与列表分组逻辑，工作量大且影响展示，不建议在 V1.0 做。

## 二、资料管理依赖分析

### 1. 数据与存储

| 项 | 位置 |
| --- | --- |
| 资料表 | `resources`（schema.sql L135-152）：元数据 + `file_key`（R2 对象键，唯一索引） |
| R2 对象 | 键前缀 `resources/<资源ID>/<随机名>.<ext>` |
| 演示数据 | `seed.sql` L544-621（5 条 demo/ 占位记录） |

### 2. 服务端依赖（`public/_worker.js`）

| 功能 | 位置 | 说明 |
| --- | --- | --- |
| 后台资料 API | `/api/admin/resources` L5270-5321（列表/新建）、`/<id>` L5323（编辑）、`/status` L5368、`/delete` L5395（软删，R2 保留）、`/<id>/file` L5422（上传 R2） | 全套 CRUD + 上传 |
| 会员资料库页 | `/member/app/resources/` → `renderResourceList` L2848 | 列 published 资料，含下载按钮 |
| 会员 SOP 页 | `/member/app/sop/` → `renderResourceList(env, member, ["sop","prompt"], ...)` L3013 | 按分类 slug 过滤 |
| 资料下载 | `/member/app/resources/<id>/download` → `handleResourceDownload` L3050 | 校验会员 + published，从 R2 取流返回；写审计 |
| 会员首页 | `renderMemberHome` L2418 | `loadPublishedResources` 统计/展示 |
| 更新页 | `renderUpdates` L2903 | 资料更新列入时间线 |
| 后台概览 | `/api/admin/overview` | 资料计数 |

### 3. 与课程系统的关系（重点确认）

**课程图片、课程 PDF 不依赖资料管理：**

| 资源类型 | 存储位置 | 元数据表 | 上传接口 | 访问路径 |
| --- | --- | --- | --- | --- |
| 课程封面/正文配图 | R2 `media/` | 无（URL 直接写在 contents.body/cover_image） | `/api/admin/uploads/image` L5070 | `/media/<name>.<ext>` 公开 |
| 课程 PDF 附件 | R2 `courses/<课程ID>/` | `content_files` | `/api/admin/contents/<id>/attachment` L4970 | `/courses/<slug>/attachment` |
| 资料管理文件 | R2 `resources/<资料ID>/` | `resources` | `/api/admin/resources/<id>/file` L5422 | `/member/app/resources/<id>/download` |

三条链路完全独立。**隐藏资料管理入口不会影响课程图片、PDF 预览与下载。**

### 4. 结论：能否隐藏后台入口？

**可以。** 隐藏只影响「新增/编辑资料」的管理操作，不影响：

- 已发布资料在会员端的展示与下载（接口与页面都在会员路由下，不经过后台页面）；
- 课程系统任何功能。

**安全方案（第二阶段执行）：**

1. 仅移除后台导航「资料管理」菜单项（`adminShell` L1535 一行）。
2. 保留：`resources` 表、`/api/admin/resources*` 全部接口、`/admin/resources/` 页面路由（建议保留作隐藏入口）、R2 文件、下载接口。
3. 会员端 `/member/app/resources/`、`/member/app/sop/` 页面保持不动，已发布资料继续可见可下载。
4. 风险：隐藏后无法通过界面新增资料（仍可用 API 或恢复入口）；这是任务书可接受的「暂时隐藏」语义。

## 三、两处改动共同的硬性约束

- 不删表、不删字段、不删 API、不删 R2 文件、不删下载接口。
- 改动仅限 `adminShell` 导航数组（`_worker.js` L1530-1540），一处两行。
- 改动后必须回归：课程列表分组、课程表单分类下拉、会员资料下载、课程附件下载、/media/ 图片访问。
