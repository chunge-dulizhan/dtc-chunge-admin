## 2. 访问保护机制（双重校验）

1. **页面层**：`GET /tools/<slug>/` → `handleToolPage`（L5850）
   - 查 `tools` 表：不存在或非 published → 404 状态页。
   - access_level=member：校验会员会话，未登录 302 到 `/member/?next=/tools/<slug>/`。
   - 校验通过才从 ASSETS 取 `public/tools/<slug>/index.html` 返回（`Cache-Control: private, no-store`）。
2. **计算层**：`POST /api/tools/<slug>/calc`（L4199-4229）
   - 每次请求重新查工具状态 + 重新校验会员会话。
   - 前端 `tools.js` L139 发起调用。
3. 下架工具：页面与计算接口同时失效。

## 4. 新增工具的成本（重要：后续复用约束）

新增一个带服务端计算的工具需要三处改动：

1. `public/tools/<slug>/index.html`（页面，参考现有 5 个）
2. `_worker.js` 增加 `calc<S slug>` 函数并注册进 `computeTool` switch
3. 后台或 seed 插入 tools 记录

**任务书要求后续优先复用现有工具、不得重新开发或破坏——现有 5 个工具的页面、计算逻辑、鉴权链路完整，直接复用即可。**
