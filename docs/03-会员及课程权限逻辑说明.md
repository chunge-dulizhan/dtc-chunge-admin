# 会员及课程权限逻辑说明

> 来源：`public/_worker.js`、`public/assets/js/admin.js`、`public/assets/js/member-login.js`。

## 1. 会员体系

### 1.1 会员创建（无公开注册）

- 唯一入口：后台「会员管理 → 添加会员」（`/admin/members/` → `POST /api/admin/members`，`_worker.js` L4312）。
- 创建函数 `createMemberWithCode`（L474）：一次事务内插入 members + access_codes，返回明文访问码（仅此一次展示，库里只存哈希）。
- 会员字段：姓名必填；联系方式、微信备注、来源、备注选填。

### 1.2 会员编号（CG 编码）规则

`nextMemberCode`（L458-472），二期第三轮已修复为「最小缺口算法」：

1. 只统计 `deleted_at IS NULL AND member_code LIKE 'CG%'` 的会员；历史 CH 编码不参与。
2. 从 CG0001 起取最小未占用序号（现有 CG0001/0002/0004 → 下一个是 CG0003）。
3. 并发安全：插入依赖 `member_code` UNIQUE 约束，冲突自动重试 3 次（L479-502）。
4. 删除会员时（003 迁移已上线）：原编号归档 `archived_member_code`，`member_code` 改写为 `DEL-编码-id`，编码立即释放可复用。

**确认：当前规则按 CG0001 开始运行，符合任务书要求。**

### 1.3 访问码

- 12 位随机字符（字母表去掉 I/L/O/0/1），展示格式 `XXXX-XXXX-XXXX`。
- 存储：`SHA-256("chunge:" + CODE_PEPPER + ":" + 规范化码)`，不明文落库。
- 重置访问码：旧码 `status='revoked'`，立即失效。

### 1.4 登录与会话

- 登录页 `/member/`（静态 `public/member/index.html` + `member-login.js`）→ `POST /api/member/login`（L375）。
- 限流：IP 与访问码双维度，15 分钟窗口内 5 次失败锁 10 分钟（`login_attempts`）。
- 会话：`chunge_member` Cookie（HttpOnly+Secure+SameSite=Lax，30 天），`sessions` 表存 token 哈希。
- **每次请求回查数据库**（`getMemberSession` L289 附近）：会话有效 + 会员未被暂停/停用/删除才放行。管理员停用会员后，其已有 Cookie 立即失效。

### 1.5 会员状态

| status | 含义 | 效果 |
| --- | --- | --- |
| `active` | 正常 | 可登录可访问 |
| `paused` | 已暂停 | 会话立即失效，登录返回 403 |
| `disabled` | 已停用 | 同上 |
| （软删除） | `deleted_at` 非空 | 访问码与会话全部失效 |

### 1.6 前台显示名称

前台统一显示「**VIP会员**」，已不再使用「永久会员」：

- 会员中心侧边栏：`{状态} · VIP会员`（`_worker.js` L1308）
- 会员首页 Hero：`正常 · VIP会员`（L2449）
- 登录页 / 首页静态页：`VIP会员`（`public/member/index.html` L100、`public/index.html` L100）
- 后台新建会员成功弹窗：`会员编号 XXXX · VIP会员`（`admin.js` L504）

数据库内部值 `member_type='lifetime'` 仅作存储，不向前台展示，无需修改。

## 2. 课程权限模型

### 2.1 两个维度

| 字段 | 取值 | 作用 |
| --- | --- | --- |
| `access_level` | `free` / `member` | 免费公开 or 会员专属 |
| `status` | `draft` / `published` / `archived` / `deleted` | 草稿 / 已发布 / 已下架 / 已删除 |

### 2.2 可见性矩阵

| 内容状态 | 公开站（/courses/、/library/、栏目页） | 会员中心 |
| --- | --- | --- |
| free + published | ✅ 可见可读 | ✅ 可见 |
| member + published | ❌ 列表不显示；直接访问 /library/ 302 去登录 | ✅ 可见 |
| draft / archived | ❌ | ❌ |
| deleted | ❌（后台也不显示） | ❌ |

### 2.3 各入口鉴权点

| 入口 | 处理 | 鉴权逻辑 |
| --- | --- | --- |
| `/courses/`、`/library/` | `handlePublicCourseList` L3244 | `status='published' AND access_level='free'` |
| `/library/<slug>/` | `handlePublicLibrary` L3115 | published；非 free 302 跳登录 |
| `/guide/` 等 4 栏目 | `handleNavSection` L3309 | published + free + `nav_category` 匹配 |
| `/member/app/courses/` | `renderCourseIndex` L2513 | 会员会话 + published（free/member 都列） |
| `/member/app/courses/<slug>` | `renderCourseDetail` L2665 | 会员会话 + published |
| `/courses/<slug>/attachment` | `handleContentAttachment` L5742 | free 公开下载；member 校验会话 |
| `/tools/<slug>/`、`/api/tools/<slug>/calc` | `handleToolPage` L5850 / L4199 | 工具 published；member 级校验会话 |
| `/member/app/resources/<id>/download` | `handleResourceDownload` L3050 | 资料 published；member 级校验会话 |

## 3. ★ 「后台创建免费公开课程，前台找不到」问题定位

代码逐层排查后，查询/路由/数据关联三层逻辑本身**没有缺陷**，问题出在以下三处「默认行为 + 静态内容」的组合：

### 原因 A（最可能）：新建课程默认值不是「免费公开 + 发布」

- 后台课程表单（`_worker.js` L1735-1736）：「权限」下拉第一项是 `会员专属`，「状态」下拉第一项是 `草稿`。
- `admin.js` L775 新建课程时显式重置 `access_level = "member"`。
- 服务端 `normalizeContentInput` L3513-3514：未传值时同样默认 `member` + `draft`。
- 结果：管理员如果只填标题正文直接保存，课程是「会员专属 + 草稿」，`/courses/` 过滤条件 `published + free` 自然查不到。

### 原因 B：栏目页多一层 nav_category 过滤

- `/guide/`、`/products/`、`/build/`、`/marketing/` 四个栏目页要求 `nav_category` 精确匹配（L3325）。
- 免费课程若未选择「导航栏目」，只出现在 `/courses/` 总列表，不会出现在任何栏目页。

### 原因 C：首页「最新免费文章」是静态写死的

- `public/index.html` L196-236 的四行文章是硬编码静态链接（指向 `/guide/90-day-roadmap.html` 等旧静态页），**不会随后台发布自动更新**。
- 其中「查看全部免费课程（后台发布后自动出现在这里）」只是一条指向 `/courses/` 的链接文案，容易让运营误以为首页会自动展示新课程。

### 修复建议（第二阶段执行，本阶段不动代码）

1. 课程表单：当「权限」选为免费公开时，醒目提示「还需把状态改为发布才会出现在前台」；或新建课程默认状态改为「发布」需确认。
2. 后台课程列表增加「前台可见性」提示列（免费公开+已发布 = 公开站可见）。
3. 首页「最新免费文章」改为动态接口（如新增 `/api/public/contents?level=free&limit=4`），或至少改掉误导性文案。
4. 栏目页空列表时给出更明确提示（现有文案已有兜底，可保留）。

## 4. 管理员权限

- 独立账号体系（`admins` + `admin_sessions`），与会员完全隔离；会员 Cookie 无法调用 `/api/admin/*`。
- 首次部署无管理员时 `/admin/` 显示初始化页（可选 `ADMIN_SETUP_TOKEN` 二次校验），创建后入口自动关闭。
- 所有管理接口：`originAllowed` 校验 + `getAdminSession` 校验（`requireAdmin` L506）。
- 密码 PBKDF2-SHA256（100000 迭代）哈希存储。
