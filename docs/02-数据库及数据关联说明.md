# 数据库及数据关联说明

> 来源：`db/schema.sql`、`db/migrations/002_phase2.sql`、`db/migrations/003_member_code_release.sql`、`public/_worker.js` 实际查询语句。生产库 = Cloudflare D1 `chunge-db`。

## 1. 表清单（14 张）

| 表 | 用途 | 关键字段 |
| --- | --- | --- |
| `members` | 会员 | `member_code`（UNIQUE）、`archived_member_code`（003 迁移新增）、`status`(active/paused/disabled)、`member_type`(默认 lifetime)、`deleted_at`（软删除） |
| `access_codes` | 会员访问码（只存哈希） | `member_id`→members、`code_hash` UNIQUE、`code_hint`、`status`(active/revoked) |
| `sessions` | 会员登录会话 | `token_hash` UNIQUE、`expires_at`、`revoked_at` |
| `admins` | 管理员 | `username` UNIQUE、`password_hash`（PBKDF2）、`status` |
| `admin_sessions` | 管理员会话 | `token_hash` UNIQUE、12 小时有效期 |
| `content_categories` | 内容分类 | `slug` UNIQUE、`type`(course/resource/tool)、`sort_order`、`status` |
| `contents` | 课程/图文 | `slug`（唯一索引）、`category_id`→content_categories、`content_type`(article/chapter)、`nav_category`(guide/products/build/marketing)、`content_format`(markdown/html)、`access_level`(free/member)、`status`(draft/published/archived/deleted) |
| `content_chapters` | 章节课程内容 | `content_id`→contents（ON DELETE CASCADE）、`sort_order` |
| `content_files` | 课程附件（每课 1 个） | `content_id` UNIQUE→contents、`file_key`（R2 键） |
| `resources` | 资料管理 | `file_key`（唯一索引）、`category_id`→content_categories、`access_level`、`status` |
| `tools` | 在线工具 | `slug` UNIQUE、`entry_url`、`access_level`、`status` |
| `cases` | 学员案例 | `slug` UNIQUE、`content_format`、`show_on_home`、`status` |
| `settings` | 网站设置键值 | `key` PK（品牌名/微信/页脚等） |
| `audit_logs` | 审计日志 | `actor_type`(member/admin/system)、`action`、`detail` |
| `login_attempts` | 登录限流 | `attempt_key` PK、`failures`、`locked_until` |

另有文案表（`loadCopy` 使用的 copy 存储，002 迁移建立，存 `public.*`/`member.*`/`admin.*` 文案键值）。

## 2. 关联关系

```
members 1───n access_codes        （访问码属于会员）
members 1───n sessions            （会员会话）
admins  1───n admin_sessions
content_categories 1───n contents （courses.category_id，可空，LEFT JOIN）
content_categories 1───n resources（resources.category_id，可空，LEFT JOIN）
contents 1───n content_chapters   （ON DELETE CASCADE）
contents 1───1 content_files      （content_id UNIQUE）
```

要点：

- **所有外键关联都是「可空 + LEFT JOIN」**：课程/资料不依赖分类必然存在。分类被删且有课程占用时，服务端拒绝删除并提示先迁移（`/api/admin/categories/<id>` DELETE 返回 409 `category_in_use`；`/migrate` 接口可先迁移再删）。
- 前台、会员端、后台查询分类全部用 `LEFT JOIN`，分类缺失时显示「未分类」兜底，不会报错。

## 3. 软删除与唯一约束策略

| 对象 | 删除方式 | 唯一约束处理 |
| --- | --- | --- |
| 会员 | 软删除（`deleted_at` 置时间） | 003 迁移：删除时把原编号归档到 `archived_member_code`，`member_code` 改写为 `DEL-原编码-id` 墓碑值，释放 CG 编码 |
| 课程 | 软删除（`status='deleted'`） | slug 改写为 `slug--del-<id>` 释放唯一索引 |
| 工具 | 软删除（`status='deleted'`） | 同上 slug 改写 |
| 案例 | 软删除（`status='deleted'`） | 同上 slug 改写 |
| 资料 | 软删除（`status='deleted'`） | R2 文件保留不删，只改状态 |

所有列表查询默认过滤 `status != 'deleted'` / `deleted_at IS NULL`。

## 6. 数据风险点（详评见《V1.0 升级风险清单》）

1. `contents.category_id` / `resources.category_id` 无外键强制删除保护之外的约束，依赖应用层维护（现状良好）。
2. `settings`、文案表为键值结构，改错键名不会报错，只会静默回退默认值。
3. D1 无自动备份，需手动 `wrangler d1 export`；R2 文件需单独用控制台/rclone 备份。
